# Self-Study Datasets for KV Cache Compression

## What is this?

Each dataset contains pre-extracted attention vectors (Q, K, V) from
**Llama 3.1 8B** over a long document, plus 1000 synthetic
question-answer conversations generated via self-study. The purpose
is to train and evaluate KV cache compression algorithms on
**realistic, unseen queries** — the kind of questions a user would
ask after the model has already processed a long context.

## The core idea

When compressing a KV cache, at
compression time we don't know what questions the user will ask.
Self-study solves this by generating diverse training queries
*offline*, before any real user query arrives.

## Dataset structure

```
{dataset_name}/
  context.txt                         # Raw corpus text
  metadata.json                       # Source, domain, original question
  self_study_conversations.jsonl      # 1000 generated (question, answer) pairs
  vectors/                            # Pre-extracted attention vectors
    metadata.json                     # Model, heads, context token count
    context/                          # Context-only K/V (shared across all conversations)
      layer_00.pt
      layer_12.pt
      layer_15.pt
      layer_27.pt
      layer_31.pt
    conversations/                    # Per-conversation QA-portion vectors
      conv_0000/
        layer_00.pt                   # Q/K/V for the QA tokens only
        ...
        layer_31.pt
        example.json                  # Question, answer, token offsets
      conv_0001/
        ...
      conv_0999/
        ...
```

## How the vectors are organized

### Context vectors (one set per dataset)

The corpus is tokenized as `"Context: {corpus}"` and fed through Llama
3.1 8B. At 5 selected layers, we extract K and V vectors for specific
attention heads. These represent the **long context KV cache** — the
thing we want to compress.

- Shape: `[context_tokens, 128]` per tensor (e.g., 23,446 tokens for Sanofi)
- Stored as bfloat16 PyTorch tensors
- Keys: `K_rope_kvhead{j}`, `K_raw_kvhead{j}`, `V_kvhead{j}`,
  `Q_rope_head{i}`, `Q_raw_head{i}`

### Conversation vectors (1000 per dataset)

For each self-study conversation, the model processes the **full
sequence**: context + question + generated answer. We then extract
Q/K/V vectors for only the **QA portion** (tokens after the context).

This is critical: the Q vectors at position `t` in the QA portion
depend on all preceding tokens (context + earlier QA tokens) through
the residual stream. They are the **realistic query vectors** that
a compressed KV cache must serve correctly.

Each conversation directory contains:

- `layer_XX.pt` — Q/K/V tensors for the QA tokens, same key naming
- `example.json` — metadata including:
  - `context_tokens`: number of context tokens (same for all convs)
  - `qa_start`: position where QA begins (= context_tokens)
  - `question_tokens`: how many tokens are the question
  - `answer_tokens`: how many tokens are the generated answer
  - `sequence_length`: total QA tokens (question + answer)
  - `seed_type`: category of the self-study question

### Question vs. generated answer within each conversation

The QA portion has two parts, stored together in the same `.pt` file:

```
[question tokens | answer tokens]
 ← question_tokens → ← answer_tokens →
```

The question was generated by an LLM (Gemini) given a chunk of the
corpus. The answer was generated by Llama 3.1 8B with greedy decoding
given the full context + question. Both are realistic queries that
exercise the KV cache.

## How to use for experiments

### Train/test split

Each conversation's `example.json` has a `"split"` field set to
`"train"` (900 conversations) or `"test"` (100 conversations),
assigned randomly with seed 42. To reassign or change the ratio:

```bash
python cartridge/datasets/assign_splits.py              # all datasets, 100 test
python cartridge/datasets/assign_splits.py --n-test 200  # custom split
```

Use Q vectors from **train** conversations as training queries for
algorithms that accept them (MQBeta, Learned coreset, etc.).
Evaluate on Q vectors from **test** conversations — specifically
the question tokens (not the model-generated answer tokens), since
those represent realistic unseen user queries.

### Loading for compression evaluation

```python
import torch, numpy as np

vectors_dir = "cartridge/datasets/multi_doc_qa_sanofi/vectors"

# 1. Load context K/V — this is the KV cache to compress
ctx = torch.load(f"{vectors_dir}/context/layer_15.pt", map_location="cpu", weights_only=True)
K_ctx = ctx["K_rope_kvhead5"].float().numpy()   # [23446, 128]
V_ctx = ctx["V_kvhead5"].float().numpy()         # [23446, 128]

# 2. Load one test conversation's Q vectors — these are unseen queries
qa = torch.load(f"{vectors_dir}/conversations/conv_0042/layer_15.pt", map_location="cpu", weights_only=True)
Q_test = qa["Q_rope_head22"].float().numpy()     # [~286, 128]
K_qa   = qa["K_rope_kvhead5"].float().numpy()    # [~286, 128]
V_qa   = qa["V_kvhead5"].float().numpy()          # [~286, 128]

# 3. Full sequence for ground-truth attention
K_full = np.concatenate([K_ctx, K_qa], axis=0)   # [23732, 128]
V_full = np.concatenate([V_ctx, V_qa], axis=0)

# 4. For each test query Q_test[t]:
#    - Ground truth = softmax(Q_test[t] @ K_full[:ctx+t+1].T / sqrt(128)) @ V_full[:ctx+t+1]
#    - Compressed  = same but with K_ctx replaced by compressed representation
#    - Error       = relative L2 between the two outputs
```

### What gets compressed vs. what stays exact

In a realistic deployment:
- **Context K/V** (23K-119K tokens) → compressed via clustering, learned coreset, etc.
- **Sink token** (position 0) → kept exact (always attended to)
- **Local window** (last 128 tokens before query) → kept exact
- **QA tokens** (question + answer so far) → kept exact (just generated)

Only the middle "residual" region of context tokens is a candidate
for compression.

## Selected attention heads

5 heads chosen by effective entropy percentile across all 256
(layer, Q-head) pairs, spanning the full entropy spectrum:

| Layer | Q Head | KV Head | Entropy | Label |
|-------|--------|---------|---------|-------|
| 31 | 14 | 3 | 0.14 | p0 (most concentrated) |
| 12 | 25 | 6 | 3.98 | p25 |
| 15 | 22 | 5 | 4.71 | p50 (median) |
| 27 | 7 | 1 | 5.64 | p75 |
| 0 | 22 | 5 | 11.03 | p100 (most diffuse) |

Concentrated heads (p0) focus attention on a few tokens — easy to
compress with top-k selection. Diffuse heads (p100) spread attention
broadly — require clustering or learned methods to compress well.

## Self-study question generation

Following Algorithm 1 from the Cartridge paper (arXiv:2506.06266):

1. Chunk the corpus into random subcorpora (2K-16K chars)
2. Sample a seed prompt from 5 categories:
   - **Structuring**: format data as JSON/YAML/XML
   - **Summarization**: summarize a section
   - **Question**: factual recall with specific details
   - **Use case**: practical downstream application
   - **Creative**: open-ended discussion
3. Gemini generates a question given the chunk + seed
4. Gemini answers it given only the chunk
5. Stored in `self_study_conversations.jsonl`

The generated questions are diverse and exercise different parts of
the context, making them a good proxy for real user queries.
